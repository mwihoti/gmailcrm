How gmailcrm uses Google user data

Last updated: June 3, 2026

Data Accessed

gmailcrm requests read-only Gmail access and Calendar event access after a user explicitly grants consent through Google OAuth.

  • Gmail metadata and snippets, including sender, subject, date, message ID, thread ID, and snippet text.
  • Calendar event information needed to check availability and create bookings.
  • OAuth tokens needed to make authorized requests on behalf of the signed-in user.

Data Use

Google user data is used only to provide user-facing CRM features: finding Gmail leads, detecting LinkedIn lead notifications, grouping recent messages by organization, checking Calendar availability, and creating Calendar bookings requested by the user.

Data Storage

For this deployment, OAuth tokens are stored in an encrypted HTTP-only browser cookie so the app can authenticate later dashboard requests. Local development may store tokens in a local tokens.json file. Gmail message content is not permanently stored by the application database.

Data Sharing

gmailcrm does not sell Google user data. The app does not share Google user data with advertising platforms or data brokers. If optional AI enrichment is configured, selected lead metadata may be sent to the configured AI provider only to generate summaries, priorities, and suggested next actions visible in the app.

Limited Use

gmailcrm's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

User Controls

Users can revoke access at any time from their Google Account permissions page. Users can also request deletion using the instructions on the delete data page.
